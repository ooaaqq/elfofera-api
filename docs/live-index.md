# EOE LIVE INDEX

## 视觉与组件

前端采用 [IBM Carbon Design System](https://carbondesignsystem.com/) 官方 `@carbon/react` 和 `@carbon/icons-react`，主题跟随系统外观并实时切换：浅色使用 White 主题的 UI Shell、Gray 10 工作区和白色内容面；深色使用 Gray 100 主题及对应的内容层级。页面背景、原生控件和浏览器主题色保持一致，使用 IBM Plex 西文字体及中文无衬线回退字体。页面使用 productive 类型样式、spacing token 和 Layer，不覆盖官方控件内部高度与全局按钮焦点。界面不放置资料来源、使用方法等常驻说明文案；档案页直接展示筛选与资料，不显示顶部大标题区；保留仅供辅助技术读取的页面 h1。文档页使用共用标题组件展示标题与导语，每页保留一个 h1。保留控件名称、数据统计、空状态和故障提示。

顶栏产品名固定为“EOE 档案”。SideNav 按“档案”和“项目”分组，提供直播档案、歌曲档案、API 使用说明和致谢四个入口；桌面始终展开，移动端由菜单按钮打开。移动导航展开时锁定背景滚动和主内容交互，焦点在菜单按钮与导航链接之间循环，支持遮罩和 Escape 关闭并返回菜单焦点。跳过导航只移动焦点，不改写 hash 路由。主内容避开 48px 顶栏和桌面 256px 侧栏，支持跳过导航。

工作区以 16px/24px 面板内边距、24px 业务栏间隔和桌面 32px 页面内边距组织，标题与正文共用对齐轴；手机主区域使用 16px 内边距。宽屏日历优先分配可用空间，详情栏宽度限制在 18–22rem；歌曲搜索与详情按 5:7 分配。业务布局根据侧栏外、扣除内边距后的实际宽度重排，页面本身不横向溢出。CSS 容器查询是详情切换与月历/列表断点的唯一来源，`use-responsive-layout.js` 读取实际布局，避免 JavaScript 重复维护宽度阈值。年份、月份、成员、标题搜索及重置采用官方 medium 尺寸。日期、计数和成员作为次级信息，场次和作品标题作为主信息；未知分类不显示。

内容分组用 Grid/Flex 的 gap 控制间距，不依赖可选标签或链接的外边距撑开布局。场次摘要与录播区间隔 24px，关联信息通常间隔 8px，曲目次级字段间隔 4px；空状态图标与标题间隔 16px。可选分 P 链接沿用所在分组间距，空标签与空事件容器不占位。

页面预留纵向滚动条空间，避免切换长短详情时滚动条出现或消失，改变日历列宽并触发标题重新换行。日历与结果行选中态使用背景和内阴影，不改变边框、内边距或字重。

## 动效与样式维护

自定义交互统一使用 Carbon 官方 productive motion token：结果行、链接和选中态使用 `duration-fast-02`（110ms）及 standard 曲线；页面内容使用 `duration-moderate-01`（150ms）及 entrance 曲线；详情内容使用 110ms 的淡入。表格、标题和列表文本不做位移，动作箭头仅在悬停时轻移 2px。焦点反馈立即生效，选中态不引起布局变化。按钮、下拉菜单、侧栏、通知与骨架保留官方交互样式。

系统开启减少动态效果时，停用所有过渡、动画和平滑滚动；不延迟资料显示或导航操作。侧栏退出后恢复背景状态，切换主视图回到内容起点，返回详情列表恢复触发按钮与原滚动位置。

`frontend/style.scss` 只组织官方组件样式与站点模块。`frontend/styles/` 按基础主题、外壳、业务布局、文档、日历、详情、歌曲、响应式和交互分别维护；交互时长与曲线直接引用官方 motion token，不再增加一套自定义数值。`page-header.jsx` 统一标题层级，`documentation-page.jsx` 只负责两页实际共用的正文与目录结构，不包装所有 Carbon 组件。

## 直播档案

- 首次进入默认选择最新年份和该年最近直播所在月份；切换年份后选择该年最近直播月份，保留成员筛选。URL 中明确提供年月时按链接显示。
- 年份、月份、成员、标题搜索与重置整合在日历面板内。年份和月份使用 Select，成员使用 Dropdown；窄面板自动分行。
- 标题搜索覆盖全部年份的实际直播，按日期从新到旧显示结果，成员筛选同时生效，每页 20 条。搜索时隐藏年月选择和场次详情，点击结果定位对应年月与场次；清空搜索恢复搜索前的日历年月与选择。重置清空成员与标题筛选，不改变年月。
- 桌面直接显示月历，小于 672px 时显示按日列表；不显示顶部“直播档案”标题区，也不额外设置重复的年月标题、场次统计或显示方式切换栏。
- 月历是带表头和日期的原生表格，场次使用按钮，不模拟缺少方向键行为的 ARIA grid。日期内保留全部匹配场次，选中场次使用选中底色和蓝色标记；月历区域支持键盘横向滚动。
- 宽工作区同时显示日历和场次详情。可用宽度不足 1024px 时，选择后进入详情，并提供“返回直播列表”，恢复触发按钮焦点和列表位置。
- 列表与紧凑详情共用页面 h1；日历、场次与曲目使用后续标题层级，不增加大型介绍区。
- 日程变更在日历中提供独立入口，不要求当日有直播。成员筛选保留该成员和未指定成员的变更；全局标题搜索仅查找实际直播。历史变更使用普通资料列表，不作为系统警报反复播报。
- 明确标记取消的计划只展示为日程变更，不计入实际直播。变更入口只展示当日变更，不附带其他直播的录播和曲目。
- 日程变更在生成时整理为带稳定标识、日期、受影响成员和明确描述的展示项。改期覆盖原日期与新日期；明确的请假和形态调整区间覆盖区间内日期，无结束日期时只登记起始日。仅有模糊原定日期的延期在关联公告日展示，保留新时间未公布，不补造具体日期。
- 阵容变更可按原成员或新成员查找；明确针对个人的取消和缺席不扩展到原周表中的其他成员。形态、时间、直播间、追加直播、暂停活动和暂定缺席分别表述，不统一简写为“日程调整”。
- 场次详情展示日期、标题、成员、已知分类与形态、突击标签、主要录播和全部已收录曲目。缺少录播或曲目时明确提示。
- 曲目包含作品、原唱、表演成员和已知形式。有切片则直达视频，无切片则明确标注为 B 站搜索。外部链接提供新窗口说明。
- 录播与曲目保留明确的合集分 P，主链接打开对应的首个分 P，其余已确认分 P 提供独立链接，不默认跳到合集 P1。

## 歌曲档案

- 未搜索时，在搜索框下用搜索结果列表直接展示演出次数较多的六首歌曲；搜索后该列表展示匹配作品，不额外设置推荐标题或独立推荐组件。未选择作品时，右侧展示收录概览：作品数量、演出记录总数、有投稿的作品数量，以及演出较多的六位原唱，原唱条目也复用搜索结果项，不另设排行标题。原唱按其作品的累计演出记录排序，同一作品的重复署名只计一次，多位原唱分别计入，不推断 EOE 演唱者；只统计有演出记录的作品，点击原唱进入相关作品搜索。输入搜索后右侧概览与原唱排行只统计匹配作品；清空搜索恢复全库概览。有投稿的作品按作品去重，不把同一投稿关联多首作品的次数当作投稿数量。窄屏从快捷入口打开歌曲后，返回恢复入口或搜索列表的焦点与位置。
- 搜索歌曲或原唱，显示真实命中总数，按演出次数排序，使用 Carbon Pagination 浏览全部匹配作品。修改查询清除旧作品选择并返回第一页；每页可选 10、20、50 条。
- 搜索与选择不依赖直播年份请求。结果列表与详情统一随页面滚动，不设置内部纵向滚动区；分页切换记录后回到对应列表开头。窄屏选择后进入作品详情，“返回搜索结果”恢复结果位置与焦点。
- 搜索结果和作品摘要分别展示演出次数与投稿条数；摘要保留标题、原唱、已知分类与系列。没有实际标签时不保留空标签占位。
- 作品详情的“作品投稿”展示明确通过 `relatedWorks` 关联的已发布事件，按日期从新到旧列出投稿日期、标题、已有成员署名和视频链接，保留分 P。投稿不受演出筛选影响，不据投稿标题推断演唱成员，也不把发布日期补算为演出日期。只有投稿的作品仍可搜索和观看，演出次数保留为 0，不展示无用的演出筛选控件。
- 作品记录覆盖全部年份与事件类型，与索引中的总数校验一致。支持年份、成员筛选和最近/最早排序，明确区分全部演出数与当前筛选数；超过 20 条时分页，不截断历史记录。
- 历史使用 ContainedList，日期、场次、成员与视频动作分层。直播记录可跳转对应年月和场次，投稿记录提供可用视频，不模拟月历跳转。
- 未搜索、无匹配作品、未选择作品、记录为空、加载中和加载失败具有不同提示与可操作入口。

## API 使用说明

`#api` 提供独立的 API 使用说明，不依赖档案清单或年份请求。页面展示公开入口、OpenAPI JSON、健康检查、时间线、歌曲搜索、表演历史、次数统计、成员代码、分页与错误语义。参数与响应以当前 `rust/http.rs`、`rust/contract.rs` 和 [查询接口](ai-api.md) 为准，接口调整时同步更新 `frontend/api-view.jsx`。

使用说明与致谢参照 [Carbon 开发文档](https://carbondesignsystem.com/developing/get-started/overview/)和[内容写作指南](https://carbondesignsystem.com/guidelines/content/overview/)，共用文档式布局：大标题与简短导语放在独立内容面，正文保留适合阅读的列宽，桌面右侧提供吸顶页内目录，窄屏改用右下角的“本页内容”按钮，向上展开目录浮层，支持选择后关闭、点击外部关闭、Tab 移出时关闭和 Escape 返回按钮焦点；短屏展开时确保当前章节条目可见。所有尺寸均按章节顺序纵向排列。标题、留白、正文与次级信息使用官方类型和 spacing token，支持系统深浅色。文案使用直接的任务标题、短段落和明确字段名。

文档标题区按内容自然撑开，正文最大宽度为 44rem，右侧目录宽 12rem，目录与正文至少间隔 48px，目录靠右并在距视口顶部 192px 处吸顶。章节之间桌面间隔 64px、手机间隔 48px，小标题与段落组成独立分组。账号列表在宽屏分为两列，技术栈只列项目名称与文档链接，按可用宽度换行；接口表格保留独立横向滚动区域。

API 说明按开始查询、时间线、歌曲搜索、表演历史、次数统计、Bun 调用、资料含义与错误处理组织。官方 CodeSnippet 提供可复制、完整展开的示例；参数表格支持窄屏横向滚动和键盘操作。健康检查以当前只读快照服务为准。目录随滚动高亮当前章节，点击跳转时保持目标章节高亮，滚动完成或用户主动滚动后恢复跟踪，避免途经章节依次闪烁。章节定位与滚动跟踪读取实际 CSS 偏移，随字体缩放保持一致。活动标记按条目实际位置与高度计算，使用 150ms productive 曲线沿条目移动，浮层使用 150ms 淡入淡出；减少动态效果时直接切换。滚动本身不修改 URL；到达页面底部不强制选中最后章节，仍以标题是否到达定位线为准。点击目录通过 `section` URL 参数定位标题并移动键盘焦点，使用平滑滚动；定位前等待字体就绪，避免首次加载时标题偏移或高亮错位；直达、刷新与浏览器前进后退直接恢复位置；切换主视图清空目录位置，保留档案与歌曲筛选。

## URL 与数据加载

hash URL 保存当前视图、年月、成员、标题查询、直播搜索页码（`archivePage`）、日期和场次，以及歌曲查询、作品、分页、演出筛选和排序。切换视图保留两边的位置，支持直达、刷新、前进与后退。连续文字输入使用 replaceState，明确的导航操作使用 pushState；链接参数在入口通过 Zod 校验，无效参数显示错误并提供返回入口。

前端仅消费 `data/calendar/confirmed/` 生成的静态数据，不读取本机 evidence。清单独立加载，包含全部实际直播的 ID、日期、标题和成员摘要，供全局搜索使用；搜索不依赖年份请求。直播年份按需请求并缓存，作品记录按作品请求，包含独立的 `performances` 和 `publications` 数组，分别校验清单中的演出与投稿总数。只接纳当前请求结果，忽略已离开视图或已切换选择的响应。请求具有 10 秒超时，不自动重试、不使用其他年份替代失败数据。

清单错误在两个视图均可见，年份与作品错误在相关区域显示，均可手动重试。加载失败不伪装成无结果。加载期间只限制相关操作，骨架与局部进度具有状态说明。

数据通过 `bun run frontend:data` 生成至 `frontend/public/data/`，包括 `manifest.json`、`years/` 和 `works/`。生成时保留静态目录、写入当前文件并清理过期文件，避免运行中的开发服务丢失目录监视。Vite 构建复制至 `frontend/dist/data/`。

HTML 和未带 hash 的 JSON 应重新验证；带 hash 的静态资源可长期缓存。服务器缓存配置由 fleet 维护。

## 开发与验证

```sh
bun run frontend:dev
bun run check
bun run frontend:build
bun run frontend:preview
```

开发服务为 `http://127.0.0.1:4173/`；构建预览为 `http://127.0.0.1:4174/`，预览前需要构建。

界面修改需核对桌面与手机、密集月份、长标题、搜索总数与末页、作品完整历史、筛选、跨年跳转、URL 恢复、失败重试，以及键盘焦点和减少动态效果。自动无障碍检查不替代人工键盘和读屏验证。
