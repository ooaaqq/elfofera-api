# EOE LIVE INDEX

## 视觉与组件

前端采用 [IBM Carbon Design System](https://carbondesignsystem.com/) 官方 `@carbon/react` 和 `@carbon/icons-react`，使用 White 主题的 UI Shell、Gray 10 工作区、白色内容面、IBM Plex 西文字体及中文无衬线回退字体。页面使用 productive 类型样式、spacing token 和 Layer，不覆盖官方控件内部高度与全局按钮焦点。界面不放置资料来源、使用方法等常驻说明文案；歌曲页从搜索区开始，不设置可见的重复页面标题，保留读屏所需的 h1。保留控件名称、数据统计、空状态和故障提示。

顶栏产品名固定为“EOE 档案”。SideNav 提供直播档案、歌曲档案和 API 使用说明三个同级入口；桌面始终展开，移动端由菜单按钮打开，支持遮罩和 Escape 关闭并返回菜单焦点。主内容避开 48px 顶栏和桌面 256px 侧栏，支持跳过导航。

工作区以 16px 面板内边距和 32px 主区域间隔组织。业务布局根据侧栏外的实际宽度重排，页面本身不横向溢出。年份、月份、成员、标题搜索及重置采用官方 medium 尺寸。日期、计数和成员作为次级信息，场次和作品标题作为主信息；未知分类不显示。

内容分组用 Grid/Flex 的 gap 控制间距，不依赖可选标签或链接的外边距撑开布局。场次摘要与录播区间隔 24px，关联信息通常间隔 8px，曲目次级字段间隔 4px；空状态图标与标题间隔 16px。可选分 P 链接沿用所在分组间距，空标签与空事件容器不占位。

页面预留纵向滚动条空间，避免切换长短详情时滚动条出现或消失，改变日历列宽并触发标题重新换行。日历选中态使用背景和内阴影，不改变边框、内边距或字重。

## 直播档案

- 首次进入默认选择最新年份和该年最近直播所在月份；切换年份后选择该年最近直播月份，保留成员筛选。URL 中明确提供年月时按链接显示。
- 年份、月份、成员、标题搜索与重置整合在日历面板内。年份和月份使用 Select，成员使用 Dropdown；窄面板自动分行。
- 标题搜索覆盖全部年份的实际直播，按日期从新到旧显示结果，成员筛选同时生效，每页 20 条。搜索时隐藏年月选择和场次详情，点击结果定位对应年月与场次；清空搜索恢复搜索前的日历年月与选择。重置清空成员与标题筛选，不改变年月。
- 桌面直接显示月历，小于 672px 时显示按日列表；不设置重复的年月标题、场次统计或显示方式切换栏。
- 月历是带表头和日期的原生表格，场次使用按钮，不模拟缺少方向键行为的 ARIA grid。日期内保留全部匹配场次，选中场次使用选中底色和蓝色标记；月历区域支持键盘横向滚动。
- 宽工作区同时显示日历和场次详情。可用宽度不足 1024px 时，选择后进入详情，并提供“返回直播列表”，恢复触发按钮焦点和列表位置。
- 页面有明确的 h1；紧凑详情状态提供独立的页面标题语义，不增加大型介绍区。
- 日程变更在日历中提供独立入口，不要求当日有直播。成员筛选保留该成员和未指定成员的变更；全局标题搜索仅查找实际直播。历史变更使用普通资料列表，不作为系统警报反复播报。
- 明确标记取消的计划只展示为日程变更，不计入实际直播。变更入口只展示当日变更，不附带其他直播的录播和曲目。
- 日程变更在生成时整理为带稳定标识、日期、受影响成员和明确描述的展示项。改期覆盖原日期与新日期；明确的请假和形态调整区间覆盖区间内日期，无结束日期时只登记起始日。仅有模糊原定日期的延期在关联公告日展示，保留新时间未公布，不补造具体日期。
- 阵容变更可按原成员或新成员查找；明确针对个人的取消和缺席不扩展到原周表中的其他成员。形态、时间、直播间、追加直播、暂停活动和暂定缺席分别表述，不统一简写为“日程调整”。
- 场次详情展示日期、标题、成员、已知分类与形态、突击标签、主要录播和全部已收录曲目。缺少录播或曲目时明确提示。
- 曲目包含作品、原唱、表演成员和已知形式。有切片则直达视频，无切片则明确标注为 B 站搜索。外部链接提供新窗口说明。
- 录播与曲目保留明确的合集分 P，主链接打开对应的首个分 P，其余已确认分 P 提供独立链接，不默认跳到合集 P1。

## 歌曲档案

- 未搜索时，在搜索框下用搜索结果列表直接展示演出次数较多的六首歌曲；搜索后该列表展示匹配作品，不额外设置推荐标题或独立推荐组件。未选择作品时，右侧展示收录概览：作品数量、演出记录总数、有投稿的作品数量，以及演出较多的六位原唱，原唱条目也复用搜索结果项，不另设排行标题。原唱按其作品的累计演出记录排序，同一作品的重复署名只计一次，多位原唱分别计入，不推断 EOE 演唱者；只统计有演出记录的作品，点击原唱进入相关作品搜索。输入搜索后右侧概览与原唱排行只统计匹配作品；清空搜索恢复全库概览。有投稿的作品按作品去重，不把同一投稿关联多首作品的次数当作投稿数量。窄屏从快捷入口打开歌曲后，返回恢复入口或搜索列表的焦点与位置。
- 搜索歌曲或原唱，显示真实命中总数，按演出次数排序，使用 Carbon Pagination 浏览全部匹配作品。修改查询清除旧作品选择并返回第一页；每页可选 10、20、50 条。
- 搜索与选择不依赖直播年份请求。结果列表与详情统一随页面滚动，不设置内部纵向滚动区；分页切换记录后回到对应列表开头。窄屏选择后进入作品详情，“返回搜索结果”恢复结果位置与焦点。
- 搜索结果和作品摘要分别展示演出次数与投稿条数；摘要保留标题、原唱、已知分类与系列。没有实际标签时不保留空标签占位。
- 作品详情的“作品投稿”展示明确通过 `relatedWorks` 关联的已发布事件，按日期从新到旧列出投稿日期、标题、已有成员署名和视频链接，保留分 P。投稿不受演出筛选影响，不据投稿标题推断演唱成员，也不把发布日期补算为演出日期。只有投稿的作品仍可搜索和观看，演出次数保留为 0，不展示无用的演出筛选控件。
- 作品记录覆盖全部年份与事件类型，与索引中的总数校验一致。支持年份、成员筛选和最近/最早排序，明确区分全部演出数与当前筛选数；超过 20 条时分页，不截断历史记录。
- 历史使用 ContainedList，日期、场次、成员与视频动作分层。直播记录可跳转对应年月和场次，投稿记录提供可用视频，不模拟月历跳转。
- 未搜索、无匹配作品、未选择作品、记录为空、加载中和加载失败具有不同提示与可操作入口。

## API 使用说明

`#api` 提供独立的 API 使用说明，不依赖档案清单或年份请求。页面展示公开入口、OpenAPI JSON、健康检查、时间线、歌曲搜索、表演历史、次数统计、成员代码、分页与错误语义。参数与响应以当前 `src/index.ts`、`src/contracts.ts` 和 [查询接口](ai-api.md) 为准，接口调整时同步更新 `frontend/api-view.jsx`。

使用官方 CodeSnippet 提供可复制的 curl 与 Node.js 示例，代码自动换行并完整展开。参数使用原生表格，页面随文档统一滚动。切换到说明页保留档案和歌曲的 URL 状态，返回后恢复原筛选与选择。

## URL 与数据加载

hash URL 保存当前视图、年月、成员、标题查询、直播搜索页码（`archivePage`）、日期和场次，以及歌曲查询、作品、分页、演出筛选和排序。切换视图保留两边的位置，支持直达、刷新、前进与后退。连续文字输入使用 replaceState，明确的导航操作使用 pushState；链接参数在入口通过 Zod 校验，无效参数显示错误并提供返回入口。

前端仅消费 `data/calendar/confirmed/` 生成的静态数据，不读取本机 evidence。清单独立加载，包含全部实际直播的 ID、日期、标题和成员摘要，供全局搜索使用；搜索不依赖年份请求。直播年份按需请求并缓存，作品记录按作品请求，包含独立的 `performances` 和 `publications` 数组，分别校验清单中的演出与投稿总数。只接纳当前请求结果，忽略已离开视图或已切换选择的响应。请求具有 10 秒超时，不自动重试、不使用其他年份替代失败数据。

清单错误在两个视图均可见，年份与作品错误在相关区域显示，均可手动重试。加载失败不伪装成无结果。加载期间只限制相关操作，骨架与局部进度具有状态说明。

数据通过 `pnpm frontend:data` 生成至 `frontend/public/data/`，包括 `manifest.json`、`years/` 和 `works/`。生成时保留静态目录、写入当前文件并清理过期文件，避免运行中的开发服务丢失目录监视。Vite 构建复制至 `frontend/dist/data/`。

HTML 和未带 hash 的 JSON 应重新验证；带 hash 的静态资源可长期缓存。服务器缓存配置由 fleet 维护。

## 开发与验证

```sh
pnpm frontend:dev
pnpm check
pnpm frontend:build
pnpm frontend:preview
```

开发服务为 `http://127.0.0.1:4173/`；构建预览为 `http://127.0.0.1:4174/`，预览前需要构建。

界面修改需核对桌面与手机、密集月份、长标题、搜索总数与末页、作品完整历史、筛选、跨年跳转、URL 恢复、失败重试，以及键盘焦点和减少动态效果。自动无障碍检查不替代人工键盘和读屏验证。
