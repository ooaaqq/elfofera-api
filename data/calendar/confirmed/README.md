# 确认资料

这里是应用和数据库导入使用的当前数据集。文件按领域和月份组织，数据结构以 `src/db/schema.ts`、导入脚本和 API 契约为准。

## 文件

- `events-YYYY-MM.json`：事件、活动、公告和已确认的发布记录。
- `performances-YYYY-MM.json`：表演与事件、作品的关联。
- `recordings-YYYY.json`：按 BV 记录的录播资料。
- `plans.json`：官方计划及关联的变更。
- `schedule-changes-YYYY-MM.json`：取消、改期、时间和形式变更。
- `songs.json`：独立作品、原唱和必要的来源摘要。
- `accounts.json`：成员、组合和主要来源账号。

每条记录保留当前结论及最小来源定位。原始图片、页面响应和完整审查报告不在仓库中；它们位于本机备份目录。

## 规则

同一场直播只保留一个事件 ID，跨日用 `endDate` 表达。断线重开、分 P、弹幕与无弹幕版本不自动增加场次。原计划不会因改期或取消删除，变更通过关联字段表达。

作品按实际身份区分；同名不同曲保留独立 ID。歌曲只采用明确切片、合集分 P 或多来源曲目资料，不逐场观看录播枚举全部演唱。原唱允许保留合理搜索匹配，但同名冲突不强行确定。

粉丝二创不进入正式作品和表演清单。缺少非关键作者信息不阻塞发布；只有会改变日期、场次、身份、作品或可用性的歧义才进入人工复核。
